# 短剧总集篇自动分集工具 · 产品需求文档（PRD）

> **版本** v2.0
> **产品形态** 本地工具 / CLI + 可选 Web UI
> **目标用户** 短剧内容整理者
> **复杂度** 0-to-1

面向拥有大量油管短剧总集篇长视频的用户，提供一条从"大文件输入"到"自动识别集边界"再到"批量裁剪输出单集"的自动化流水线工具。核心价值：把人工打点的工作量压缩到最低。

---

## 1 需求背景

### 1.1 业务触发源

用户手上持续积累从油管下载的短剧总集篇长视频——单文件时长一小时以上、体积数百 MB。这些总集篇把一部短剧的多集（通常 10–30 集）首尾拼接在一起，没有任何章节标记或元数据。用户需要把它们拆成一集一集的独立文件，方便单独观看、归档或二次分发。

### 1.2 当前痛点

目前唯一的拆分方式是全程人工打点：打开视频播放器，逐段快进寻找每集的开始和结束位置，手动记录时间戳，再用剪辑软件逐段裁剪。一小时的总集篇，手动打点通常要花 20–40 分钟，且容易遗漏或记错时间点。当用户手上有数十个总集篇需要处理时，这个工作量完全不可接受。

更棘手的是，总集篇的拼接方式不统一——有的在集与集之间插入黑帧过渡，有的直接硬切，有的每集带固定片头标题卡。没有任何单一规则能覆盖所有情况，人工打点时也需要逐个视频重新摸索规律。

> **PM 判断**
> 这是一个典型的"重复劳动自动化"场景。核心难点不在裁剪（FFmpeg 一行命令就能切），而在**如何自动识别每一集的边界时间点**。如果能把这个识别过程自动化到 80% 以上准确率，剩余部分用人工快速复核，就能把单视频处理时间从 30 分钟压缩到 5 分钟以内。

---

## 2 需求目标

基于用户场景和痛点分析，本工具的核心目标可以量化为以下几个指标：

| 目标维度 | 指标 | 说明 |
|----------|------|------|
| 自动识别准确率 | ≥ 80% 的集边界可自动定位 | 剩余 20% 通过人工复核界面快速修正，非全自动也非全手动 |
| 单视频处理时间 | ≤ 10 分钟（含复核） | 1 小时视频，自动分析 ≤ 5 分钟，人工复核 ≤ 5 分钟 |
| 裁剪输出质量 | 无损模式默认，切口偏差 ≤ 2 秒 | 默认 `-c copy` 流复制不重编码，可选精确重编码 |
| 使用门槛 | 无需手动打点，无需懂命令行 | Web UI 可视化操作；CLI 也可直接用 |

这些指标背后的设计哲学是：自动化不追求 100%，而是把人工从"全程打点"压缩到"少量复核"。只要自动检测能把大部分边界定位正确，剩余的复核工作量就远低于纯手动。这是效率与可靠性的最佳平衡点。

---

## 3 数据流向与模块关系

工具按使用流程分为四个功能模块，用户按顺序走完即完成一次分集任务。模块之间通过结构化数据（候选点 JSON、时间清单 JSON）传递信息，各模块可独立调试和替换。

```
模块一：文件输入与任务配置
    │ 输出：VideoMeta + AppConfig
    ▼
模块二：自动分析与检测
    │ 输出：四路候选点 JSON → 融合时间清单 JSON
    ▼
模块三：时间清单查看与人工复核
    │ 输出：修正后的时间清单 JSON
    ▼
模块四：批量裁剪与输出
    │ 输出：N 个单集视频文件
    ▼
  [完成] → 可回到模块一处理下一个视频
```

模块二内部，四类信号检测器并行运行，各自产出候选边界点，再由融合决策引擎合并为统一时间清单。四路检测器的详细技术原理见技术方案文档。

## 4 功能需求详情

### 4.1 模块一：文件输入与任务配置

**页面布局**

本模块分为三个区域：顶部的文件拖拽/选择区，中部的文件信息展示条（文件加载后出现），以及底部的任务配置面板（文件加载后出现）。配置面板包含 OCR 引擎选择、裁剪模式、文件命名模板、抽帧间隔四项配置。

**业务逻辑**

用户通过拖拽或点击选择一个视频文件后，系统调用 ffprobe 读取文件元信息（格式、分辨率、时长、编码），在文件信息条中展示。文件确认后展开配置面板，用户根据需要调整参数。OCR 引擎默认 RapidOCR（纯 CPU 轻量），短剧标题识别已够用；如需更高精度可切 PaddleOCR。裁剪模式默认无损快速。文件命名模板支持 `{ep}` 占位符表示集数，`{ep:02d}` 表示零填充两位。点击"开始分析"后进入模块二。

**交互逻辑**

- 拖拽文件进入上传区 → 区域高亮变色 → 松开时触发文件加载
- 点击上传区 → 弹出系统文件选择器 → 选择后触发文件加载
- 文件加载中 → 上传区显示加载动画 → 完成后切换为文件信息条 + 配置面板
- 点击"移除" → 清空文件，回到初始上传区状态
- 配置项变更即时生效，无需额外保存

**字段规则**

| 字段 | 类型 | 必填 | 默认值 | 说明 |
|------|------|------|--------|------|
| 视频文件 | 文件路径 | 是 | — | 支持 mp4/mkv/mov，单文件 ≤ 2GB |
| OCR 引擎 | 枚举 | 是 | RapidOCR | RapidOCR / PaddleOCR |
| 裁剪模式 | 枚举 | 是 | 无损快速 | 无损快速 / 精确重编码 |
| 文件命名模板 | 文本 | 是 | `第{ep:02d}集.mp4` | 支持 {ep} 和 {ep:0Nd} 占位符 |
| 抽帧间隔 | 枚举 | 是 | 0.5 秒 | 0.25s / 0.5s / 1.0s，影响 OCR 精度与速度 |

**边界与异常**

- 文件格式不支持 → 上传区提示"不支持的格式，请选择 mp4/mkv/mov 文件"
- 文件超过 2GB → 提示"文件过大（当前 {size}GB），建议先用 FFmpeg 按时间拆分为更小的段再处理"。2GB 限制的依据：无损裁剪需约等于原文件大小的磁盘空间，2GB 单文件在普通家用磁盘上留有充足余量；同时 OCR 抽帧的中间产物（约 7200–14400 张 PNG）也会占用数 GB 临时空间，过大的源文件会导致中间产物爆炸
- ffprobe 读取失败 → 提示"无法读取视频信息，文件可能已损坏"
- 视频无音轨 → 警告"未检测到音轨，音频指纹和静音检测将自动跳过"，允许继续（仅依赖 OCR 和场景检测）
- 视频时长 < 60 秒 → 提示"视频过短，可能不是总集篇，是否继续？"

### 4.2 模块二：自动分析与检测

**页面布局**

本模块分为三层：顶部的总体进度条（汇总四路检测的整体完成度），中部的四通道状态卡片（每个信号检测器一张卡片，显示名称、状态标签、进度条和简述），底部的实时日志区（滚动输出检测过程中的关键事件）。

**业务逻辑**

用户点击"启动检测"后，系统并行启动四类信号检测器：OCR 标题识别（抽帧 → OCR → 正则匹配集数）、音频指纹片头检测（Chromaprint 提取指纹 → 滑窗自相关找重复片头）、黑帧静音检测（FFmpeg blackdetect + silencedetect 取交集）、场景聚类检测（PySceneDetect 场景切换 + 时长聚类）。每个检测器独立运行，各自产出候选边界点列表。全部完成后，系统自动运行融合决策引擎，合并候选点、对齐集数序列、标注置信度，生成最终时间清单。

四路检测器并行运行而非串行，总耗时取决于最慢的一路而非四路之和。OCR 通常是瓶颈（需要逐帧识别文字），其他三路相对较快。检测过程中各检测器将中间结果（候选点 JSON）写入工作目录，即使后续步骤崩溃，已完成的检测结果不会丢失。

**交互逻辑**

- 点击"启动检测" → 按钮变为禁用态，四通道状态从"等待"变为"进行中"
- 各通道进度条实时更新 → 完成后状态变为"完成"，进度条变绿
- 某通道失败 → 该卡片状态变红，显示错误简述，不影响其他通道
- 日志区实时滚动输出关键事件（如"OCR 识别到第3集 @ 00:12:35"）
- 全部完成 + 融合决策完成 → 出现"查看结果"按钮，引导进入模块三
- MVP 阶段不支持检测过程中断；后续版本可加"暂停/取消"功能

**边界与异常**

- 某路检测器报错 → 该通道标记为"失败"，不影响其他通道；融合时跳过该信号
- 四路全部失败 → 提示"自动检测失败，请尝试手动模式"并引导至模块三的手动打点界面
- 检测耗时超过预估 → 日志区显示当前进度和预估剩余时间
- OCR 识别到 0 集 → 警告"未识别到集数标题，可能该视频无标题卡或标题样式特殊"，融合引擎降级为按时间自动编号模式
- 融合后低置信度集占比 > 50% → 警告"超过一半的集为低置信度，建议仔细复核或尝试调整参数重试"

### 4.3 模块三：时间清单查看与人工复核

**页面布局**

本模块自上而下分为三层：时间轴可视化区（用色块展示每集在整条视频中的位置和占比，颜色深浅表示置信度），集数清单表格（列出每集的集数、起止时间、时长、置信度、操作按钮），以及选中集的详情面板（展示边界点附近的帧预览缩略图和微调操作）。底部是复核摘要和"全部确认"入口。

**业务逻辑**

系统展示融合后的时间清单，每一行代表一集，包含集数、开始时间、结束时间、时长和置信度评级。置信度分三级，判定条件如下（三份文档统一以此为准）：

| 置信度 | 判定条件 | 处理方式 |
|--------|----------|----------|
| **高** | OCR 集数命中 + 至少 1 个其他信号（音频指纹/黑帧静音/场景聚类）在 ±3 秒窗口内同时命中 | 直接裁剪，无需复核 |
| **中** | 仅 OCR 命中（无其他信号佐证），或推断补全的集但有 ≥ 2 个其他信号佐证 | 裁剪但建议快速复核 |
| **低** | 推断补全且其他信号佐证 < 2 个，或仅单一弱信号命中，或集数序列有断点 | 必须人工复核后确认 |

用户的核心操作是对低置信项进行快速复核——点击表格行或时间轴片段，查看边界点附近的帧预览，确认时间是否正确或微调后确认。全部确认后进入模块四。

**交互逻辑**

- 点击时间轴上的色块 → 对应表格行高亮选中，底部展开详情面板
- 点击表格行 → 时间轴对应色块高亮，展开详情面板
- 详情面板中"微调时间" → 时间字段变为可编辑输入框，用户修改后实时更新时间轴
- 详情面板中"确认此集" → 该行置信度标记为"已确认"，色块变为绿色边框
- 底部"全部确认" → 所有未确认项批量标记为已确认，跳转模块四
- 未复核的低置信项在"全部确认"时弹出提醒"有 N 集低置信项未复核，是否继续？"

**字段规则**

| 字段 | 类型 | 可编辑 | 格式 |
|------|------|--------|------|
| 集数 | 整数 | 是 | 1, 2, 3...（支持手动改编号） |
| 开始时间 | 时间戳 | 是 | HH:MM:SS.ms |
| 结束时间 | 时间戳 | 是 | HH:MM:SS.ms |
| 置信度 | 枚举 | 否（系统标注） | 高 / 中 / 低 / 已确认 |

**边界与异常**

- 集数序列有断点（如识别到 1,2,4,5 缺 3）→ 缺失行用虚线标出，提示"第 3 集未检测到，点击添加"
- 用户手动添加缺失集 → 在时间轴上选一段区间，指定集数后插入
- 时间冲突（两集时间重叠）→ 标红提示，不允许确认直到修正
- 用户手动修改导致某集时长 < 30 秒 → 警告"该集时长异常短，请确认是否正确"

### 4.4 模块四：批量裁剪与输出

**页面布局**

本模块自上而下分为三部分：输出配置区（输出目录、裁剪模式、文件命名预览，以及"开始裁剪"按钮），裁剪进度区（总体进度条和当前状态），输出文件列表（每集的文件名、大小、时长和完成状态）。裁剪全部完成后底部出现完成提示和后续操作入口。

**业务逻辑**

用户确认时间清单后进入本模块。系统根据模块一配置的裁剪模式和文件命名模板，逐集调用 FFmpeg 进行裁剪。无损模式下使用 `-c copy` 流复制，不重编码，速度极快；精确重编码模式下使用 `libx264` 重编码，保证帧级精确但耗时较长。每集裁剪完成后实时更新文件列表中的状态。全部完成后展示汇总信息（总集数、总体积、输出路径）。

**交互逻辑**

- 点击"开始裁剪" → 按钮变为禁用，进度区展开，文件列表逐行更新状态
- 裁剪中 → 进度条实时更新，文件列表中当前正在裁剪的行显示"进行中"动画
- 单集完成 → 该行状态变为"已完成"，进度条推进
- 全部完成 → 出现完成提示条，展示"打开输出目录"和"处理下一个视频"按钮
- 点击"打开输出目录" → 调用系统文件管理器打开输出路径
- 点击"处理下一个视频" → 回到模块一初始状态，开始新一轮任务

**边界与异常**

- 输出目录不存在 → 自动创建
- 磁盘空间不足 → 裁剪前预估所需空间（按视频文件大小 × 集数占比估算），不足时提示"预计需要 {X}GB，当前可用 {Y}GB"并阻止开始
- 单集裁剪失败 → 该行标红，显示错误信息，不影响其他集；用户可重试该集
- 文件名冲突 → 自动追加序号后缀，如 `第01集_1.mp4`
- 裁剪输出文件时长为 0 → 标记为失败，提示"该集时间区间可能无效"

## 5 非功能需求

| 维度 | 要求 |
|------|------|
| 操作系统 | Windows 10+、macOS 12+、Ubuntu 20.04+（需支持 FFmpeg 4.4+） |
| Python 版本 | 3.10+（使用 match/case、类型联合语法） |
| 硬件最低配置 | 4 核 CPU、8GB 内存、20GB 可用磁盘空间；GPU 非必需（PaddleOCR 可选 GPU 加速） |
| 外部依赖 | FFmpeg 4.4+（含 ffprobe）、Chromaprint fpcalc（可选，缺失时音频指纹检测自动跳过） |
| 处理性能 | 1 小时视频（720p）：自动分析 ≤ 5 分钟（OCR 瓶颈），无损裁剪 ≤ 3 分钟 |
| 内存约束 | OCR 抽帧分批处理，单批 ≤ 500 帧，峰值内存 ≤ 2GB |
| 日志 | 全程结构化日志（JSON 格式），输出到终端和工作目录 `run.log`；日志级别 INFO（默认）/ DEBUG（-v） |
| 配置校验 | 启动时校验 config.yaml 参数合理性（如 min_episode_sec < max_episode_sec），不合理项报错退出 |
| 中断恢复 | 检测阶段各信号独立写入候选点 JSON，崩溃后可从已有 JSON 恢复，无需重新检测已完成的信号 |

## 6 错误恢复与异常处理

工具在任一阶段失败时，应提供明确的恢复路径，而非直接退出。

| 失败场景 | 恢复策略 |
|----------|----------|
| 文件加载失败 | 回到模块一初始状态，保留用户已填配置 |
| 某路检测器崩溃 | 该路跳过，其余路正常完成；融合时该路无候选点 |
| 四路检测全部失败 | 引导至模块三手动打点界面，用户可完全手动指定边界 |
| 融合引擎异常 | 降级输出各路原始候选点（未合并），用户手动选择 |
| 裁剪中途磁盘满 | 已裁剪的集保留，未完成的集标记失败，提示清理空间后重试 |
| 裁剪单集失败 | 不影响其他集，失败集可单独重试 |
| 工具整体崩溃 | 工作目录下保留各阶段中间产物（候选点 JSON、时间清单 JSON），重启后可从断点恢复 |

断点恢复机制：模块二每完成一路检测即将结果写入 `work_dir/candidates/<signal_type>.json`；融合完成后写入 `work_dir/time_list.json`。工具重启时检查这些文件是否存在，存在则跳过对应步骤。

## 7 非目标

明确不在本期范围内的事项，避免范围蔓延。

| 非目标项 | 原因 |
|----------|------|
| 视频内容理解 / 剧情摘要 | 本工具只做结构性分割，不做语义分析 |
| 自动下载油管视频 | 下载由用户自行完成（已有成熟工具如 yt-dlp） |
| 云端处理 / 在线服务 | 本期定位为本地工具，不涉及云端部署 |
| 多用户 / 权限管理 | 本地单用户工具，无需账号体系 |
| 批量队列管理 | 本期一次处理一个视频。批量队列可后续迭代加入 |
| 视频转码 / 格式转换 | 裁剪保持原格式原编码。如需转码用户可用 FFmpeg 自行处理 |
| 插件 / 扩展系统 | 本期不提供插件接口，检测器为内置固定四路 |
| 云端同步 / 备份 | 配置和时间清单均为本地文件，不涉及云端同步 |
| 实时预览裁剪效果 | 裁剪为批量离线操作，不提供实时预览 |
| 自动字幕提取 / 生成 | 字幕处理不在本期范围 |

2. Chromaprint — 音频指纹库，用于全曲识别、重复音频检测。 https://github.com/holeg/chromaprint
3. FFmpeg blackdetect — 用黑帧检测滤镜定位场景边界。 https://ffmpeg-cookbook.com/en/articles/black-detect/
4. Jellyfin Intro Skipper — 基于 Chromaprint 音频指纹的片头片尾自动检测方案。 https://blog.csdn.net/gitblog_00217/article/details/151446701
5. RapidOCR — 基于 ONNX Runtime 的轻量 OCR 引擎，纯 CPU 即可运行。 https://github.com/RapidAI/RapidOCR
