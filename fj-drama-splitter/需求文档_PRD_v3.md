## 1. 项目概述

### 1.1 背景与问题

用户从 YouTube 下载短剧"总集篇"长视频（时长 1 小时以上，文件几百 MB）。这类总集篇只是将多集短剧连续拼接在一起，**没有自带章节标记、没有元数据**，无法直接知道每一集的起止时间。

手动观看视频逐帧找分割点极其耗时，需要一个自动化工具来：

1. 自动分析视频/音频内容，推断每一集的分割时间点
2. 根据时间点自动裁剪，输出独立单集视频文件

### 1.2 核心目标

构建一个 **本地运行的 Python Web 应用**，能够：

- 利用多种信号源（视频闪白、音频静音、字幕间隙）自动识别集间分割边界
- 多信号交叉验证，提高分割准确率，降低误检率
- 支持人工确认/修正分割点
- 根据确认后的时间清单批量裁剪输出单集视频
- 支持批量并发处理多个总集篇文件

### 1.3 目标用户

| 维度 | 描述 |
|------|------|
| 身份 | 个人短剧爱好者 / 自媒体创作者 |
| 技术背景 | 具备基本计算机操作能力，能看懂时间戳格式，能做简单的人工确认操作 |
| 使用频率 | 不定期使用（有新总集篇下载时） |
| 核心痛点 | 手动找分割点耗时数小时；现有工具不支持多信号交叉验证；裁剪后台词串集 |
| 期望 | 上传文件后几分钟内得到分集清单，确认后一键裁剪输出 |

### 1.4 MVP 范围定义

本产品采用迭代开发，MVP（最小可行版本）范围如下：

| 范围 | MVP（P0） | 后续迭代（P1/P2） |
|------|-----------|-------------------|
| 信号源 | 闪白检测、静音检测、字幕解析 | 自适应阈值、场景切换检测 |
| 交叉验证 | 三重/双重/单信号降级 | 信号权重、VTT逐词增强 |
| 人工干预 | 确认/编辑/增删分割点 | 帧预览、拖拽时间轴 |
| 裁剪 | 无损裁剪、批量并发 | 输出校验、重试机制 |
| 批量处理 | 单任务完整流程 | 多任务队列管理 |

## 2. 使用场景

### 场景一：全自动模式（全部信号源）

```
用户上传 mp4 + mp3 + txt/vtt 字幕文件
  → 系统分别执行：闪白检测 / 音频静音检测 / 字幕静默区间提取
  → 三重交叉验证：闪白点 ∩ 静音点 ∩ 字幕间隙 → 高置信度分割点
  → 仅有两个信号吻合 → 高置信度分割点
  → 仅一个信号 → 低置信度分割点
  → 生成 [{集数, 开始时间, 结束时间, 置信度}] 清单
  → 用户在 Web 界面确认/微调
  → 确认后自动裁剪输出
```

### 场景二：全自动模式（部分信号源）

```
用户上传 mp4 + mp3（无字幕）
  → 闪白检测 + 音频静音检测双重验证
  → 两信号吻合 → 高置信度；单信号 → 低置信度
  → 生成带置信度的分集清单
  → 用户确认后裁剪

用户上传 mp4 + txt/vtt 字幕（无音频）
  → 闪白检测 + 字幕交叉验证
  → 两信号吻合 → 高置信度；单信号 → 低置信度
  → 生成带置信度的分集清单
  → 用户确认后裁剪
```

### 场景三：全自动模式（仅视频）

```
用户上传 mp4（无字幕、无音频）
  → 仅闪白检测
  → 所有分割点均为低置信度
  → 人工确认时重点审查
  → 确认后裁剪
```

### 场景四：人工输入模式

```
用户已从其他渠道（如 AI 分析字幕文本）得知每集起始时间
  → 用户在 Web 界面粘贴起始时间列表（如 00:00:00, 00:02:30, 00:05:00）
  → 系统自动计算每集结束时间（= 下一集开始时间，最后一集 = 视频总时长）
  → 系统用字幕校验切割点是否切在台词中间，给出警告提示
  → 用户确认/微调
  → 确认后自动裁剪输出
```

## 3. 功能需求

> 置信度评定规则（适用于全部功能需求）：
> - **HIGH（高）**：2 个及以上信号源在匹配窗口内吻合
> - **LOW（低）**：仅 1 个信号源检出
> - **不存在 MEDIUM 级别**

### 3.1 文件输入

| 编号 | 需求 | 用户故事 | 优先级 |
|------|------|---------|--------|
| F-IN-01 | 支持上传 mp4 格式视频文件 | 作为用户，我希望上传 mp4 视频以便系统分析分集 | P0 |
| F-IN-02 | 支持上传 mp3 格式音频文件（可选，YouTube 单独下载） | 作为用户，我希望上传音频以提高分集准确率 | P0 |
| F-IN-03 | 支持上传 txt 格式字幕文件（内容为 SRT 格式，可选） | 作为用户，我希望上传 SRT 字幕以启用台词防串集 | P0 |
| F-IN-04 | 支持上传 vtt 格式字幕文件（WebVTT 格式，可选） | 作为用户，我希望上传 VTT 字幕以获得更精确的时间戳 | P0 |
| F-IN-05 | 字幕文件二选一即可。若同时提供 txt 和 vtt，系统使用 vtt（含逐词时间戳更精确），并在界面提示用户已选择 vtt | 作为用户，我希望系统自动选择更精确的字幕格式 | P1 |
| F-IN-06 | 音频与视频时间轴对齐，系统无需额外同步处理 | 作为用户，我希望直接上传已对齐的音视频 | P0 |
| F-IN-07 | 支持批量上传多个总集篇文件，排队处理 | 作为用户，我希望一次上传多个文件批量处理 | P1 |
| F-IN-08 | 输入视频文件大小上限不低于 2GB（Gradio 默认上传限制需调整至 2GB 以上） | 作为用户，我希望上传大文件不受限制 | P0 |
| F-IN-09 | 上传时校验文件类型（按文件头魔数校验，非仅后缀） | 作为用户，我希望系统拒绝无效文件并给出提示 | P1 |

### 3.2 自动分集检测（核心）

#### 3.2.1 视频闪白检测

| 编号 | 需求 | 说明 | 优先级 |
|------|------|------|--------|
| F-VF-01 | 闪白检测 | 通过逐帧/采样帧分析画面亮度，检测"突然变白/变亮"的过渡点作为集间边界候选 | P0 |
| F-VF-02 | 闪白特征约束 | 闪白特征：亮度骤升至接近白色（阈值可配），持续零点几秒后回落。需区分集间闪白与集内正常场景切换 | P0 |
| F-VF-03 | 亮度回落检测 | 除检测亮度骤升外，还应检测骤升后的回落，形成完整的闪白特征匹配 | P2 |

#### 3.2.2 音频静音检测

| 编号 | 需求 | 说明 | 优先级 |
|------|------|------|--------|
| F-AU-01 | 静音区间检测 | 通过分析 mp3 音频能量曲线，检测短时能量骤降/静音区间作为集间边界候选 | P0 |
| F-AU-02 | 静音特征约束 | 集间停顿特征：音频能量骤降至接近静音（阈值可配），持续 0.5-3 秒后恢复。需区分集间停顿与集内正常对话间隙 | P0 |
| F-AU-03 | 独立分集能力 | 有音频时，即使没有视频闪白信号，也能仅凭音频静音检测实现分集 | P0 |
| F-AU-04 | 自适应阈值 | 根据音频整体能量分布动态调整静音阈值，适配不同视频的音量水平 | P2 |

#### 3.2.3 多信号交叉验证

| 编号 | 需求 | 说明 | 优先级 |
|------|------|------|--------|
| F-CR-01 | 三重交叉验证 | 有全部信号源时，闪白点 ∩ 静音点 ∩ 字幕间隙三者交叉验证 | P0 |
| F-CR-02 | 双重验证降级 | 仅有两个信号源时，双重交叉验证，吻合点标记为 HIGH | P0 |
| F-CR-03 | 单信号降级 | 仅有单一信号源时，直接使用该信号，标记为 LOW | P0 |
| F-CR-04 | 置信度标记 | 每个分割点标注置信度：HIGH（2+信号吻合）、LOW（单信号）。不存在 MEDIUM 级别 | P0 |
| F-CR-05 | 台词防串集 | 最终切割点必须保证不将一句台词切成两集。有字幕时，切割点优先选在台词间隙 | P0 |
| F-CR-06 | 微调策略 | 有字幕时，将切割点微调至最近的字幕静默区间中点，确保不切在台词中间 | P0 |

#### 3.2.4 分集清单输出

| 编号 | 需求 | 说明 | 优先级 |
|------|------|------|--------|
| F-EP-01 | 输出分集清单 | 生成 `[{集数, 开始时间, 结束时间, 置信度}]` 列表，集数从 1 开始递增 | P0 |
| F-EP-02 | 第一集开始时间 | 默认为 00:00:00（视频开头） | P0 |
| F-EP-03 | 最后一集结束时间 | 默认为视频总时长 | P0 |
| F-EP-04 | 空结果处理 | 当所有信号源均未检出分割点时，返回单集（整片为第一集），并提示用户切换人工输入模式 | P0 |

## 5. 约束条件

1. **不接入 AI/LLM**：所有分集检测纯靠程序算法（亮度分析 + 音频能量分析 + 字幕解析），不调用任何大模型 API
2. **无独显环境**：算法需在纯 CPU 上运行，不能依赖 CUDA/GPU 加速
3. **精度容忍度**：切割点允许有几秒误差（关键帧对齐限制），但**绝对不能让台词串集**（一句台词被切成两集）
4. **人工确认不可省略**：无论自动检测还是人工输入，裁剪前必须有用户确认步骤
5. **音频与视频时间轴对齐**：用户提供的 mp3 与 mp4 时间轴对齐，系统无需额外同步
6. **单机本地运行**：不依赖外部服务（数据库、消息队列等），任务状态保存在内存中

## 6. 数据生命周期

| 数据类型 | 存储位置 | 生命周期 | 清理策略 |
|---------|---------|---------|---------|
| 上传文件 | `uploads/{task_id}/` | 任务期间 | 任务完成后可手动清理；应用退出时自动清理 |

| 任务状态 | 内存 | 会话期间 | 应用重启后清空 |

## 7. 验收标准

| 编号 | 验收项 | 标准 | 验证方法 |
|------|--------|------|---------|
| AC-01 | 自动分集检测（三重验证） | 对测试视频+音频+字幕，能检测出 ≥ 95% 的真实分割点，误检率 ≤ 5% | 准备 3 个已知分割点的测试视频，对比检测结果与标注数据 |
| AC-02 | 自动分集检测（仅视频） | 对测试视频（无音频无字幕），能检测出 ≥ 80% 的真实分割点，误检率 ≤ 15% | 准备 3 个测试视频（仅视频），对比检测结果 |
| AC-03 | 台词不串集 | 所有最终切割点均不在台词中间（有字幕时） | 检查每个切割点是否落在字幕 [start, end] 区间内 |
| AC-04 | 人工输入模式 | 用户粘贴起始时间后，能正确生成完整分集清单并给出台词冲突警告 | 输入已知时间戳，验证分集清单和冲突检测 |
| AC-05 | 人工确认 | 用户可查看、编辑、增删分割点，确认后触发裁剪 | 在界面执行完整确认流程 |
| AC-06 | 裁剪输出 | 输出文件命名正确、格式正确、可正常播放 | 用 ffprobe 验证输出文件，用播放器播放验证 |
| AC-07 | 批量处理 | 可同时处理多个总集篇，并发裁剪正常 | 上传 3 个文件，验证并发裁剪 |
| AC-08 | 本地运行 | 全程在本地运行，无需联网 | 断网环境下完成完整流程 |
| AC-09 | 置信度规则 | 2+信号吻合标记为 HIGH，单信号标记为 LOW，不存在 MEDIUM | 检查分集清单中的置信度标记 |
| AC-10 | 空结果处理 | 所有信号源均未检出时，返回单集并提示切换人工模式 | 上传无闪白特征的视频，验证提示 |

## 8. 风险评估

| 编号 | 风险 | 概率 | 影响 | 应对策略 |
|------|------|------|------|---------|
| R-01 | 闪白检测误检率高（集内闪白被误判为集间） | 中 | 高 | 交叉验证降低误检；MIN_EPISODE_DURATION 过滤；人工确认兜底 |
| R-02 | 静音阈值不适配所有视频 | 中 | 中 | 提供可配置阈值；P2 迭代增加自适应阈值 |
| R-03 | ffmpeg 关键帧对齐导致切割偏差 | 高 | 低 | 切割点微调到字幕静默区间，偏差仍在静默区间内不影响 |
| R-04 | 大文件上传超时 | 低 | 中 | 调整 Gradio 上传限制；提供文件大小校验提示 |
| R-05 | 内存不足（处理超长视频） | 低 | 高 | 采样帧处理而非全帧加载；RMS 流式计算 |
| R-06 | VTT 逐词标记格式变化 | 低 | 低 | 正则匹配容错；提供格式异常提示 |

## 9. 术语表

| 术语 | 含义 |
|------|------|
| 总集篇 | 将多集短剧拼接在一起的长视频 |
| 闪白 | 集与集之间的过渡特效，画面突然变白/变亮，持续零点几秒 |
| 静音区间 | 音频中能量骤降至接近静音的时间段，对应集间停顿 |
| 字幕文件 | 支持 txt（内容为 SRT 格式）和 vtt（WebVTT 格式）两种。用户从 YouTube 下载 |
| 台词串集 | 一句台词的起止时间跨越了切割点，导致该台词被分到两集中 |
| 流拷贝 | ffmpeg `-c copy` 模式，直接拷贝音视频流不重编码 |
| 置信度 | 分割点的可靠程度，由信号源吻合数量决定：**HIGH**（2+信号吻合）、**LOW**（仅1信号）。不存在 MEDIUM 级别 |
| 三重交叉验证 | 闪白检测 + 音频静音检测 + 字幕间隙三种信号源互相验证，提高分割准确率 |
| 匹配窗口 | 交叉验证中判断两个信号是否"吻合"的时间容差范围（默认 ±3 秒） |
| 信号源 | 检测分割点的三种来源：flash（闪白）、silence（静音）、subtitle（字幕间隙） |
